# Contributing to Loopforge

Thanks for helping shape a calmer way to build.

## Development loop

1. Fork the repository and create a focused branch.
2. Run `npm install` and `npm run dev`.
3. Keep product behavior, styling, and copy changes scoped to one coherent improvement.
4. Run `npm run build` before opening a pull request.
5. Describe the user problem, the interaction change, and any future-facing trade-offs.

## Design principles

- Reduce cognitive load before adding functionality.
- Make the current objective obvious within one glance.
- Prefer meaningful states over placeholder content.
- Keep controls keyboard reachable and visibly focused.
- Use the orange signal color sparingly: it means action, momentum, or attention.

## Pull requests

Include screenshots for meaningful visual changes, note responsive considerations, and call out any migration or persistence implications. Do not add credentials, generated build output, or unrelated formatting churn.
